# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

JCM800 2203 amplifier model for the Digilent Arty A7-100T (part `xc7a100tcsg324-1`). Audio I/O is via a Digilent Pmod I2S2 (CS5343 ADC + CS4344 DAC) on the JA header. The DSP chain (`jcm800`) is a 16×-oversampled preamp cascade (V1A→Gain→V1B→V2A→V2B, where V1B is the 10 kΩ unbypassed cold clipper after the gain pot and V2A is the 820 Ω recovery stage — stage names are signal-chain positions, not physical valve assignments) followed by a Master Volume attenuator, a long-tailed-pair phase inverter, a push-pull EL34 power stage with shared-screen sag, an output-transformer model (primary-inductance HPF + core-sat soft-clip + leakage LPF), and a closed NFB loop with a Presence control. Gain, Master, and Presence are log-taper pots driven by `gain_pot_pos` / `master_pot_pos` / `presence_pot_pos` (8-bit, 0..255 ≈ −60..0 dB — see `scripts/gen_log_taper.py`).

## Build / run commands

Vivado batch flow driven from `Makefile`:

- `make` / `make synth` — build bitstream (`build/arty_top/arty_top.runs/impl_1/arty_top.bit`)
- `make project` — create the Vivado project only (runs `tcl/project.tcl`, which also generates the `clk_wiz_mclk` Clocking Wizard IP)
- `make program` — load the bitstream onto the board over JTAG (`tcl/program.tcl`)
- `make gui` — open the project in the Vivado GUI
- `make lint` — RTL elaboration-only syntax check via `synth_design -rtl` (fast, no mapping)
- `make clean` — remove `build/`, `.Xil`, and stray `vivado*.{jou,log,str}` artifacts

Common overrides: `make VIVADO=/path/to/vivado JOBS=4 PART=...`. `vivado` must be on `PATH`.

There is currently no simulation or unit-test harness — `make lint` is the only pre-bitstream correctness check.

## Architecture

Hierarchy (top → leaves):

```
arty_top                      rtl/arty_top.sv         board wrapper, Pmod JA pin fan-out, status LEDs
├── pmod_i2s2                 rtl/pmod_i2s2.sv        MMCM + I2S controller + Pmod pin wiring
│   ├── i2s_clkgen            rtl/i2s_clkgen.sv       wraps Clocking Wizard IP clk_wiz_mclk (100 MHz → 12.288 MHz MCLK)
│   └── i2s_controller        rtl/i2s_controller.sv   I2S TX/RX shift registers + MCLK↔sys_clk CDC
└── jcm800                    rtl/jcm800.sv           16×-oversampled DSP chain
    ├── upsample_16x          rtl/oversample/...      48 kHz → 768 kHz (4 halfband stages)
    ├── preamp                rtl/preamp.sv           V1A → [Gain pot] → V1B → V2A → V2B cascade
    │   ├── gain_stage ×4     rtl/gain_stage.sv       triode LUT+PCHIP, ×G, plate LPF, shelf, coupling HPF
    │   └── level_ctrl        rtl/level_ctrl.sv       log-taper pot between V1A and V1B (Preamp Volume)
    ├── level_ctrl            rtl/level_ctrl.sv       log-taper pot between preamp and PI (Master Volume)
    ├── phase_inverter        rtl/phase_inverter.sv   V3 long-tailed pair (A + anti-phase B); sums NFB into cathode
    ├── power_amp             rtl/power_amp.sv        push-pull EL34 + shared screen + output transformer
    │   ├── pentode_stage ×2  rtl/pentode_stage.sv    EL34 Ik LUT+PCHIP, ×G, ×vg2_ratio, |·|·IG2_RATIO
    │   ├── screen_supply     rtl/screen_supply.sv    RC leaky integrator on shared Vg2 (47 µF, 1 kΩ stopper)
    │   └── output_transformer rtl/output_transformer.sv  Ip_A−Ip_B, HPF(Lp) → sat LUT → LPF(Lleak)
    ├── nfb_network           rtl/nfb_network.sv      1-sample z⁻¹ of v_sec, ×NFB, presence shelf+pot
    └── downsample_16x        rtl/oversample/...      768 kHz → 48 kHz  (decimates v_sec to the DAC)

arty_top also instantiates the UART host interface:
  uart_rx                     rtl/uart_rx.sv          8N1 115200 baud receiver (sys_clk domain)
  uart_pot_regs               rtl/uart_pot_regs.sv    2-byte command parser → gain / master / presence registers
```

Signal-chain position of the three runtime controls mirrors the real 2203:

- **Gain** (Preamp Volume) — log-taper attenuator *inside* `preamp.sv`, between `u_v1a` and `u_v1b`. `v1a_tap` remains the pre-pot V1A output.
- **Master Volume** — log-taper attenuator *inside* `jcm800.sv`, between `u_preamp`'s output and `u_pi`'s input, so the phase inverter and power amp see the attenuated drive level.
- **Presence** — attenuator *inside* `nfb_network.sv` sitting AFTER the presence shelf, so pot=0 drops the NFB shelf output to near-zero (feedback reverts to flat) and pot=255 applies the full HF lift.

All three instances use `rtl/level_ctrl.sv` + `lut_out/log_taper_256.mem` (256 × Q0.24 audio-taper coefficients, generated by `scripts/gen_log_taper.py`). All three pots are driven by `uart_pot_regs` (opcodes `0x01` gain, `0x02` master, `0x03` presence). Reset defaults in the register file are `0x80 / 0x80 / 0x80` — the board boots audible without UART traffic, with presence at the stock 2203 "noon" setting.

The cascade Gss product to V2A's grid is large by design (≈ +79 dB at `gain_pot_pos = 255`, ≈ +49 dB at 128, ≈ +34 dB at 64). The gain pot's lower third (≤ 32) is the clean window; 32–96 is the breakup transition; ≥ 96 drives V2A into hard rail-to-rail clipping at any non-trivial input. That is the canonical cranked-2203 character — V2A behaving as a near-full-wave rectifier at high preamp-volume settings is intended, not a headroom bug.

`rtl/jcm800_pkg.sv` defines `sample_t` = `logic signed [23:0]` — the shared audio word type; anything touching samples should `import jcm800_pkg::*`. Power-amp-specific constants live in `rtl/jcm800_power_pkg.sv` (auto-generated by `scripts/gen_pentode_lut.py` alongside the EL34 / OT / NFB .mem files in `lut_out/`).

### Power amp NFB loop

The feedback path is closed: `output_transformer.v_sec` is captured by `nfb_network`, delayed by one 768 kHz sample (`z⁻¹` register, ~1.3 µs — breaks the algebraic loop cleanly), scaled by `NFB_Q4_20`, shaped by the presence shelf, attenuated by the presence pot, and subtracted from the PI's shared-cathode drive inside `phase_inverter.sv`. At the oversampled rate the one-sample delay is a negligible phase shift in-band (≪ 1° at 1 kHz) and stays well below the Nyquist-pole margin of the loop.

### Clock / timing facts that drive the I2S logic

- System clock: 100 MHz at port `clk` (XDC: `sys_clk`).
- MCLK: 12.288 MHz from the Clocking Wizard (auto-named clock `clk_out1_clk_wiz_mclk`).
- LRCK = 48 kHz, SCLK = 3.072 MHz, 32 bits per channel, 24-bit audio, MSB-first, 1-SCLK delay after LRCK edge.
- `i2s_controller` uses a free-running 8-bit MCLK counter: `count[7]`=LRCK, `count[6:2]`=bit position 0–31, `count[1:0]`=sub-SCLK phase. SCLK = `count[1]` (toggles on every 2 MCLKs). The ratios MCLK/SCLK=4 and SCLK/LRCK=64 are baked into this scheme — don't change MCLK or bit width without reworking the counter.

### CDC discipline

The sample interface crosses MCLK ↔ sys_clk via **toggle-style synchronizers** in `i2s_controller`:
- RX: `rx_done_toggle` (MCLK) → 3-FF synchronizer (sys_clk), edge-detect → `sample_valid` pulse.
- TX: `tx_ready_toggle` (sys_clk) → 3-FF synchronizer (MCLK), edge-detect → latch `tx_data_latched`.
- Synchronizer flops are annotated `(* ASYNC_REG = "TRUE" *)`.

`constraints/constraints.xdc` `set_false_path`s both directions between `sys_clk` and `clk_out1_clk_wiz_mclk`. If you rename the Clocking Wizard IP or output clock, **update these false_path lines** or timing will fail.

All Pmod I2S pins plus `rst_btn`, UART, and LEDs are false-pathed in the XDC — I/O timing is not analyzed and any new clocked I/O must add its own constraints.

### Reset

`rst_btn` is active-LOW (Arty RESET button, C2). `arty_top` gates it with `locked` to form `rst_n = rst_btn & locked`, and most async resets in the design use that composed signal. `pmod_i2s2` passes the raw `rst_btn` and gates internally.

### Top-level I/O assumptions

Port-name-to-pin mapping lives in `constraints/constraints.xdc`. Pmod JA top row = DAC (MCLK/LRCK/SCLK/SDIN), bottom row = ADC (MCLK/LRCK/SCLK/SDOUT); both rows share the same clocks driven from the FPGA. If you add/rename a top-level port, update the XDC — unconstrained ports currently DRC-warn (NSTD-1 / UCIO-1 downgraded to warning) rather than erroring.

## Vivado flow notes

- `tcl/project.tcl` creates the project under `build/arty_top/` and generates the `clk_wiz_mclk` IP (MMCM, 100 → 12.288 MHz, active-LOW resetn, locked output). Rerunning uses `-force`, which overwrites the existing project.
- `tcl/synth.tcl` opens the project and runs `synth_1` then `impl_1` to `write_bitstream`, erroring if either run's PROGRESS isn't 100%.
- `tcl/program.tcl` opens the hardware manager and programs the first `xc7a100t_0` device it finds.
- `tcl/lint.tcl` takes `<part> <rtl files...>` as `-tclargs` and runs `synth_design -rtl -top arty_top` — elaboration only, no netlist.
